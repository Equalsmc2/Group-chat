Soul Seekers Combat Monitor — Firestore Rules snippet

The desktop Combat tab reads/writes one document:
  collection: combatState
  document: party

In Firebase Console > Firestore Database > Rules, add this MATCH BLOCK
INSIDE your existing `match /databases/{database}/documents { ... }` section.
Keep your existing `messages`, `musicLibrary`, and other rules.

    match /combatState/{documentId} {
      allow read: if true;
      allow create, update: if documentId == 'party';
      allow delete: if false;
    }

IMPORTANT SECURITY NOTE
The current website does not use Firebase Authentication. "Observer" is a UI
role, not a secure login, so Firestore cannot verify that a write came from the
DM. The site hides editing controls unless Observer is selected, but anyone who
can load a public copy of the site could select Observer or write directly to
the Firebase project if public writes are enabled.

For a private table this may be acceptable. For a public deployment, use
Firebase Authentication and restrict combatState writes to a DM/admin account.

If the Combat tab says "LOCAL ONLY · CHECK FIRESTORE RULES", the browser keeps
its changes locally, but other screens will not receive them until Firestore
access is allowed.
