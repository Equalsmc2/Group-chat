Soul Seekers music library — OPTIONAL Firestore Rules snippet

The v13 player reads/writes the new collection: musicLibrary
Document ID: the 11-character YouTube video ID.

In Firebase Console > Firestore Database > Rules, add the MATCH BLOCK below
INSIDE your existing `match /databases/{database}/documents { ... }` section.
Keep every existing rule for `messages` and other collections. Do not replace
your entire Rules file with this snippet.

    match /musicLibrary/{videoId} {
      allow read: if true;
      allow create, update: if
        videoId.matches('^[A-Za-z0-9_-]{11}$') &&
        request.resource.data.keys().hasOnly(['id', 'title', 'artist', 'url', 'updatedAt']) &&
        request.resource.data.keys().hasAll(['id', 'title', 'artist', 'url', 'updatedAt']) &&
        request.resource.data.id == videoId &&
        request.resource.data.title is string &&
        request.resource.data.title.size() > 0 &&
        request.resource.data.title.size() <= 200 &&
        request.resource.data.artist is string &&
        request.resource.data.artist.size() <= 120 &&
        request.resource.data.url == 'https://www.youtube.com/watch?v=' + videoId &&
        request.resource.data.updatedAt is timestamp;
      allow delete: if false;
    }

IMPORTANT SECURITY WARNING:
Because the current site has no user authentication, these rules allow ANYONE
who knows your Firebase project/site to add or modify song entries. The input
and field limits reduce accidental junk; they do not prevent spam or abuse.
For a public deployment, use Firebase Authentication plus owner/admin-only
writes or a trusted server endpoint instead of public write access.

If the library says "Firestore rules deny writes", your links are still saved
locally in that browser. Update the rules if appropriate, return to the site,
and press SYNC. The assistant cannot publish Firebase rules remotely for you.
